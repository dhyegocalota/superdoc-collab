# Web UI

## React events and state
- A key handler that decides from React state can read a stale closure in a real browser while jsdom passes. Decide from `event.currentTarget.value`. (apps/web/src/features/timeline/filter-box.tsx, docs/learnings/2026-10-17-a-key-handler-that-reads-react-state-sees-the-previous-keystroke.md)
- A handler that consumes a key calls `event.preventDefault()`; document-level handlers check `event.defaultPrevented` and stand down. (filter-box.tsx, apps/web/src/features/timeline/use-time-travel.ts, apps/web/src/features/editor/superdoc-editor.tsx)
- A container that unmounts and remounts (a collapsed panel) is measured through a callback ref, never a ref object read once in an effect. (apps/web/src/lib/use-element-width.ts)
- `scrollIntoView` runs on state transitions only (running → result), never on every key change and never on the first render with a cached result. (apps/web/src/features/timeline/selection-summary-card.tsx)
- Every time on screen goes through `apps/web/src/lib/format-date-time.ts` with the effective zone from `useTimeZone()` and the `en-US` locale; its `Intl.DateTimeFormat` instances are cached per zone and options. Nothing else formats a time. (ADR 0024)

## Layout
- Below `lg` the documents list is stacked rows (title clamped to two lines, one muted line), never a table, and no page scrolls sideways at 320 px. (apps/web/src/features/documents/document-table.tsx, docs/features/mobile-horizontal-scroll/spec.md)
- The documents home opens in cards (`DocumentsView.Cards`), stored under `superdoc-collab.documents-view`; a stored value that is not a `DocumentsView` is removed. The grid is one column, two from `sm`, three from `lg`, four from `xl`; each card is one link with an image of the first page when the list carries `thumbnailUpdatedAt`, otherwise a CSS-drawn thumbnail of the server's preview (no SuperDoc), and `content-visibility: auto` with `contain-intrinsic-size`, so off-screen cards cost no layout. (apps/web/src/features/documents/use-documents-view.ts, apps/web/src/features/documents/document-card.tsx, docs/features/documents-cards/spec.md)
- The editor page captures the first `.superdoc-page` with `html-to-image` (`toCanvas`, `pixelRatio` 1, `THUMBNAIL_WIDTH_PX` wide, WebP at `THUMBNAIL_QUALITY`) `THUMBNAIL_CAPTURE_DELAY_MS` after the last editor update, and once on `pagehide` through `sendBeacon` when an update is waiting. Readers and an unsynced connection never capture, a capture above `THUMBNAIL_MAX_BYTES` is rendered once at half width and then dropped, a failure warns once per session, and the editor container counts delivered uploads in `data-thumbnail-uploads`. The card image falls back to the preview when it fails to load. (apps/web/src/features/editor/use-thumbnail-capture.ts, apps/web/src/features/editor/capture-thumbnail.ts, apps/web/src/features/documents/document-thumbnail.tsx, ADR 0045)
- `html-to-image` renders the page inside an SVG `foreignObject`; the rendering is faithful for SuperDoc's absolutely positioned text runs, fonts and embedded images, and costs a 60 to 70 ms long task on the first capture. (docs/features/faithful-thumbnails/spec.md, ADR 0045)

## Focus and keyboard
- A Radix `Dialog` opened without a `DialogTrigger` returns focus to `body` on close. Pass `onCloseAutoFocus` that prevents the default and focuses the opener. (apps/web/src/features/editor/editor-header.tsx, docs/learnings/2026-10-17-a-radix-dialog-without-a-trigger-drops-focus-to-body.md)
- A Dialog opened from a dropdown item needs the menu `modal={false}`, or closing leaves `pointer-events: none` on `body`. (refinement-ux-care spec)
- A roving tabindex gives exactly one element `tabIndex 0` and the rest `-1`; tests pin exactly that. (apps/web/src/features/timeline/streamgraph.tsx)
- A tooltip shown on keyboard focus but not after a pointer selection resets its keyboard flag on pointer press, not only on focus, and ends the press on release. (streamgraph.tsx)
- A sentinel that receives focus is visible while focused (`sr-only focus:not-sr-only`). (superdoc-editor.tsx)
- A `keydown` inside an iframe never reaches the parent. Forward the intent with a typed `postMessage`, validated by origin and source. (apps/web/src/features/versions/version-view-page.tsx, docs/learnings/2026-10-17-keydown-inside-an-iframe-never-reaches-the-parent.md)
- Keyboard shortcuts come from one registry, `shortcuts.ts`, which feeds the handler, the hints, the toolbar tooltips and the dialog. An entry SuperDoc consumes itself is `native`: listed, never intercepted. The handler is bound in the editor header, so it exists only on the document page, matches `event.code` (⌥ and ⇧ change `event.key`), stands down on `defaultPrevented` and on a text field with content, consumes only the keys it ran, and opens the dialog on `?` only outside every text control, because the editing surface is a textarea. (apps/web/src/features/shortcuts/use-shortcuts.ts, docs/features/word-like-shortcuts/spec.md)

## Motion
- Chart motion is paths and transforms only. `useTweenedPaths` interpolates band paths with `d3-interpolate-path` in one `requestAnimationFrame` loop and snaps under `prefers-reduced-motion`, above `MAX_TWEENED_BANDS`, on a width change, on a band whose segment count changes and on a path the library rejects. A pulse, chip ring or live dot fires once per data change from `useTimelineChange` (never on mount, never while the pointer presses the chart), and the `aria-live` text is throttled to `LIVE_ANNOUNCE_MS`. (apps/web/src/features/timeline/use-tweened-paths.ts, apps/web/src/features/timeline/use-timeline-change.ts, apps/web/src/features/timeline/use-change-pulse.ts, docs/features/streamgraph-motion/spec.md)

## Theme and panel position
- The theme applies before the first render: an inline script in `index.html` reads `superdoc-collab.theme` and adds `dark` to `html` before the bundle runs, and `useTheme()` listens to the `storage` event so another tab follows. The script cannot import, so a test pins its key to `THEME_STORAGE_KEY`. (apps/web/index.html, apps/web/src/lib/use-theme.ts, apps/web/src/lib/theme-script.test.ts)
- The editor toolbar shows SuperDoc's own ruler button (off on every open, not stored) and document-mode dropdown for Owner and Editor; `measurement-unit` stays excluded, and a Reader has no toolbar row. The Theme button beside Summarize stores an `EditorThemePreset` name or a `#rrggbb` accent under `superdoc-collab.editor-theme` (a value that is neither is removed and Default applies) and applies it with SuperDoc's `createTheme` as `sd-theme-editor` on `html`. The theme writes `--sd-editor-accent`, `--sd-editor-accent-hover` and `--sd-editor-accent-text` through `light-dark()`, and `globals.css` maps `--sd-ui-action*` to them with the app's `--primary` as the fallback, because the `html:root` block outranks a theme class; Default adds no class. (apps/web/src/features/editor/editor-theme.ts, apps/web/src/features/editor/use-editor-theme.ts, apps/web/src/features/editor/theme-button.tsx, apps/web/src/styles/globals.css, docs/features/toolbar-ruler-mode-theme/spec.md)
- The version frame is same-origin: it runs the same inline script and receives the same `storage` event, so it follows the theme with no message. (apps/web/src/features/versions/version-view-page.tsx)
- The panel position lives under `superdoc-collab.edits-panel` as a `PanelPosition`. Below `LARGE_BREAKPOINT_PX` it is always `Bottom`; with no stored value it follows `WIDE_BREAKPOINT_PX` live; a stored value that is not a `PanelPosition` is removed. (apps/web/src/features/timeline/use-panel-position.ts, apps/web/src/lib/breakpoints.ts)
- SuperDoc's local caret is an overlay `div` painted with `currentColor`, so `caret-color` does nothing; colour it through `[data-v2-local-selection-caret='true']`. (apps/web/src/styles/globals.css, docs/features/dark-theme/spec.md)

## Copy
- Every string lives in a `*-copy.ts` file or `libs/types`, never inline in JSX. (apps/web/src/lib/app-copy.ts, features/*/…-copy.ts)
- A message with a verb is a sentence and ends with a period; labels, headings and noun-phrase states ("No edits yet", "Link copied") do not. (refinement-ux-care spec P2-17)
- The ellipsis is `…`, never `...`. (refinement-ux-care spec P2-17)
- A disabled control carries a visible reason, linked with `aria-describedby`. Exception: while the document loads, SuperDoc's loading overlay on the paper is the visible reason, so the Download description may be screen-reader only. (docs/learnings/2026-10-17-a-disabled-button-never-shows-its-title.md)

## Open progress
- Opening a document shows one centred panel (`OpenProgressPanel`) with a stage list, a bar and a live detail line, never before `OPEN_PROGRESS_DELAY_MS` after `DocumentPage` mounts (`useDelayedReveal`, keyed by the document id so it never returns once shown), and never after the first `.superdoc-page .superdoc-fragment` is in the editor container (`useHasPaintedParagraph`). Stages: Preparing from the open answer's `bootstrap` (readiness Waiting while Queued or Preparing, Failed shows the existing error card), Downloading until `onCollaborationReady`, Rendering until the first fragment; Uploading belongs to the documents home, driven by `XMLHttpRequest` upload progress because `fetch` reports none over HTTP/1.1. A bar is determinate only for a real number: bytes sent, the larger of bytes received (`done` over `total`) and elapsed over the server's `estimatedMs` capped at 95% while Preparing (the SDK host sends its state only at the end, so the bytes alone sit still). (apps/web/src/features/open-progress/, apps/web/src/features/documents/upload-progress-status.tsx, docs/features/open-progress/spec.md)
- The uploader keeps the uploaded `File` in memory (`keepLocalFile`, one file at a time) and, while the open answer is Queued or Preparing, `DocumentPage` mounts `LocalPreview`: a viewing-mode `SuperDoc` built by `previewSuperdocOptions` from those bytes, with no room, under the open-progress panel as a translucent card that stays until the live editor has painted (a failed preview keeps one status line). SuperDoc converts in its own document worker, so the Preparing panel keeps counting; the preview is destroyed and the file dropped in the render that mounts the live editor, with no reload. A Create answer (the device creator of ADR 0049) is Ready at once, and, on a device that reports at least `DEVICE_PREVIEW_MIN_MEMORY_GIGABYTES` of memory (`canPreviewOnDevice`; the overlap of two engines peaked above 4 GB), the same preview is mounted from the kept file as an overlay while the Create editor converts: its engine and its frozen pages are dropped with the layer at the editor's first painted paragraph, and the page's own panel ("Preparing on this device · about N s") stays until the collaborative editor reports ready and the first paragraph is painted. Once the preview shows pages the panel has a minimize control that turns it into a thin top bar with the stage and the estimate, and a control on the bar maximizes it back; the state lives in the page only. An upload from a wide device that reports `DEVICE_FIRST_MIN_MEMORY_GIGABYTES` (`isDeviceFirst`) is sent with `preparation=device`; a device that reports less, or does not expose its memory, sends the server path. A refused upload (`UploadRefusal`) offers "Prepare on this device" unless `deviceRefusalOf` says the viewport is narrow or `navigator.deviceMemory` is below `DEVICE_PREPARATION_MIN_MEMORY_GIGABYTES`. (apps/web/src/features/local-preview/, apps/web/src/features/documents/upload-message.tsx, ADR 0049)
- The panel hides while the connection is Failed or the file failed to load, so it never covers the banner, and it hides SuperDoc's own `.v2-document-loading-overlay` while it shows. (apps/web/src/features/editor/document-page.tsx, apps/web/src/features/editor/editor-surface.tsx)

## Banners
- A page-level state banner (`ConnectionBanner`, `VersionBanner`) sits full width between the top bar and the content, carries `data-testid` and `data-state`, and wraps its action under the text at narrow widths (`flex-wrap`, `gap-2`, `px-4 py-2`, `text-sm`). `role="status"` announces progress; only a failure uses `role="alert"`. A spinner carries `motion-reduce:animate-none`. (apps/web/src/features/editor/connection-banner.tsx, apps/web/src/features/versions/version-banner.tsx)

## SuperDoc 2.23.0 in the browser
- The collaboration provider and its WebSocket live inside SuperDoc's collaboration worker: `superdoc.provider` offers only `sendStateless` and `superdoc.socket` is never set, so the page cannot count received frames or bytes. Load progress available on the main thread is `onCollaborationReady`, `onCollaborationConnectionChange` and `onPaginationUpdate` (`totalPages` laid out so far, never the total). (apps/web/src/features/editor/superdoc-editor.tsx, docs/features/open-progress/spec.md)
- The editing surface is a `textarea`, not a contenteditable; in viewing mode it is a `role="document"` element. (`EDITING_SURFACE_SELECTOR` in superdoc-editor.tsx, `EDITOR_INPUT_SELECTOR` in e2e/editor.ts)
- Any focus of a fresh blank document without a click (a programmatic `focus()` from `onReady` or `onCollaborationReady`, `reveal` of a position, or a browser-tool fill of the textarea) leaves the composition textarea focused without a selection, and the first keystroke throws "This edit couldn't be completed". The editor opens with a caret by pressing a synthetic pointer sequence (`pointerdown`, `mousedown`, `pointerup`, `mouseup`, `click`) at the first `.superdoc-fragment`, once collaboration is ready and never for a reader; browser tools still drive a document with a click, End and key presses. (apps/web/src/features/editor/use-caret-on-open.ts, docs/features/caret-on-open/, docs/learnings/2026-10-17-focusing-a-new-superdoc-document-before-the-first-click-crashes-the-first-keystroke.md, docs/learnings/2026-10-18-an-mcp-fill-on-a-blank-superdoc-surface-is-rejected-because-no-selection-exists.md)
- `onException` reports `code: 'edit-rejected'` once per rejected document-surface event (key, paste, cut, drop, pointer up), for example a keystroke aimed at a paragraph another author deleted; the instance keeps syncing, so the editor shows a status line instead of the fatal message (`exceptionOutcome` in superdoc-exceptions.ts). (docs/features/editor-survives-rejected-edits/)
- `zoom: { mode: 'fit-width' }` in the config, and `setZoomMode`, `setZoom` and `focus()` on the instance, exist. (apps/web/src/features/editor/superdoc-zoom.ts)
- The version viewer fits the page to the frame width with the shared `FIT_WIDTH_ZOOM` (`fit-width`, capped at 100 %) and `FITTED_PAGE_CLASS`, and passes no toolbar container. It takes the author palette from `authorPaletteOf`, the helper the live editor uses. (apps/web/src/features/editor/superdoc-zoom.ts, apps/web/src/features/versions/version-viewer.tsx)
- `ui: { comments: { layout: 'auto', responsive: { breakpoint } } }` moves the tracked-change and comment cards inline below the breakpoint; the default sidebar layer squeezes the page to a thumbnail at 375 px. (apps/web/src/features/editor/superdoc-options.ts)
- A remote caret in the overlay (`.v2-collaboration-overlay__remote-caret`) carries no client or user id in the DOM, only its label text (the peer's own name), `data-peer-rank` and its background colour. A caret belongs to a member only when label and colour both match the member's name and `--author-N` colour, and exactly one caret matches. A peer can still forge both; the limit is a jump to the wrong cursor, never an edit. (apps/web/src/features/editor/use-member-cursors.ts)
- Comment highlight colours come from `--sd-comment-highlight-internal` and `--sd-comment-highlight-external`. (apps/web/src/styles/globals.css)
- The toolbar is `ui.toolbar` with a `container`, `responsiveTo: 'container'` and `excludeItems`; the list is declared `satisfies readonly ToolbarItemId[]` so a name SuperDoc does not know fails the typecheck. The container is `inert` while a past version shows, and the Summarize button sits outside it. (apps/web/src/features/editor/superdoc-options.ts, apps/web/src/features/editor/editor-toolbar-row.tsx)
- The top-bar Find button calls `superdoc.emit('search:open')`, the event the toolbar's search item sends. `ui.search.open()` returns ok and mounts nothing. `ui.search: true` is what makes Cmd+F and Ctrl+F work. (apps/web/src/features/editor/find-button.tsx)
- The print view is a non-collaborative viewing-mode SuperDoc with `layoutEngineOptions.virtualization.enabled: false`. Virtualization off still paints only the pages near the viewport, so its container is sized to the `.superdoc-page` count times 1056 px, and `window.print()` runs only after every page holds a `.superdoc-fragment` (a blank page has a fragment and no text), found with a bounded `requestAnimationFrame` loop, never a timer. (apps/web/src/features/versions/print-view.tsx, docs/features/final-visuals/spec.md)
- `user.color` must be a six-digit hex: hsl, rgb and named colours are stored but the remote-caret overlay replaces them with a palette colour. The `--author-N` tokens are therefore declared as hex and read with `getComputedStyle`. (apps/web/src/features/editor/superdoc-editor.tsx, apps/web/src/styles/globals.css)
- Awareness carries only user fields, no cursor and no block id, and `scrollToElement` returns false for every id. A jump to a member finds the `.v2-collaboration-overlay__remote-caret` whose label carries the name and calls `scrollIntoView`; no caret element means online but not in the document. (apps/web/src/features/editor/use-member-cursors.ts)
- A catalogued SuperDoc command runs through `superdoc.ui.commands.get(id)`: `getState().supported` says whether it exists, `execute(payload)` runs it (`text-align` takes `left`, `center`, `right` or `justify`; `linked-style` takes a style id; `font-size` takes the size as a string). SuperDoc consumes ⌘B, ⌘I, ⌘U, ⌘Z, ⌘Y, ⌘⇧Z, ⌘⌥1 to ⌘⌥3, ⌘K and ⌘⇧L, E, R, J, X, 7, 8 on its own, and ⌘F opens its search without consuming the key. It has no subscript or superscript command. `ui.toolbar.strings` replaces a toolbar item's tooltip text and keeps its `aria-label`. (apps/web/src/features/shortcuts/shortcuts.ts, apps/web/src/features/shortcuts/toolbar-shortcut-strings.ts, docs/features/word-like-shortcuts/spec.md)
