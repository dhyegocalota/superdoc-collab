## Adversarial review

The reviewer picks the three claims most likely to be wrong and tries to refute each.

- [ ] Claim 1: a visitor can never write — attack: send a raw sync update on the public socket, with and without `readOnly`; result: a raw sync update over `/collaboration/public` with a valid token was answered `readonly`, then neither a fresh reader state nor the owner text held the marker; a BroadcastStateless frame closed 1008 `Public readers may only sync and read awareness`; a 1 MiB frame closed 1009. Held (the flag-lifted variant is covered by the unit mutation checks only).
- [ ] Claim 2: nothing public starts model, projection or version work — attack: walk every route under `/api` without a session and count worker jobs; result: not run: worker-job counting needs a counter on the stack; the 401/404 sweep above and `public-allowlist.test.ts` (7 passed in the 73) are the only evidence.
- [ ] Claim 3: a missing id and a flag-off id are indistinguishable — attack: compare status, body, headers and timing; result: status and body equal for a random id and a never-public id (e2e); after switch off the same 404; the same room token on the socket after switch off was refused `permission-denied` 1008. Timing not measured.

## Coverage honesty

What is not tested and why.

- The per-address window keeps one window per address in memory — the helper is shared with the upload budget; the accepted risk is memory growth under an address-rotating flood, bounded by the rate of new addresses a single host can present.
- Real SuperDoc rendering of a visitor's cursor colour — only the Playwright walk sees it.
